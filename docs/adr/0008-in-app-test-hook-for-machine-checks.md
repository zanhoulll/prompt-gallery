# 应用内测试钩子：raw_input_hook 注入 + GPU 回读截图 + 文件 IPC

> **2026-10-19 注记：本能力与版本号无关。** 每个 debug 构建都带 `PROMPT_GALLERY_TEST_HOOK` 钩子，实机验收一律先用它（`tools/hookdrive.py`），不要退回前台截图——见 `AGENTS.md`。正文「`Cargo.toml` 仍为 0.1.3」是写作时的快照，已过期；「v0.1.3 的实机验收被……卡死」记的是引入钩子的起因，不代表该能力只在 0.1.3 可用。

v0.1.3 的实机验收被 Windows 前台与遮挡卡死：`PrintWindow(hwnd, hdc, 2)` 对 wgpu 窗口稳定返回整幅纯黑（argb = -16777216），屏拷贝回退抓到的是占前台的 Chrome / 全屏游戏，合成输入也因抢不到前台而到不了应用（SetForegroundWindow 单独调用失败，PostMessage 直投 WM_MOUSEMOVE / WM_LBUTTONDOWN / WM_LBUTTONUP 对 egui 无效；Alt 键技巧虽有效，但要在每一步输入 / 截图前重做，且激活仍会吞掉第一下点击）。因此改为把测试能力做进应用：环境变量 `PROMPT_GALLERY_TEST_HOOK=<dir>` 门控（未设置时零行为变化），真实现整块位于 `#[cfg(debug_assertions)]`，release 只留零尺寸 stub（`from_env() -> None`、`tick()` 空），发布产物因此不含「注入输入 + 任意截图落盘」的能力。注入走 `eframe::App::raw_input_hook`（在 egui 处理本帧之前调用），事件直接写进 `raw_input.events`，命中判定与真实鼠标走同一条链路；截图走 `ViewportCommand::Screenshot(UserData)` → `Event::Screenshot`，由 egui-wgpu 做 GPU 回读，与窗口是否在前台、是否被遮挡无关；指令通道是文件 IPC：驱动追加 `<dir>/requests.jsonl`、应用逐帧出队执行、每步往 `<dir>/responses.jsonl` 追加一条应答、截图落 `<dir>/shots/*.png`，驱动 await 应答而不是 sleep。坐标按客户区物理像素收发，内部除以 `pixels_per_point`。egui 是反应式的：应用空闲后就不会再有帧、`raw_input_hook` 也不再被调用，而在 hook 里调 `request_repaint_after` 会被 eframe 按 `cumulative_pass_nr` 判为过期请求丢弃（实测启动后只跑 2 帧就永久空闲），因此钩子启用时起一个 16ms 的保活脉冲线程调用 `ctx.request_repaint()`，`Drop` 时置停止位。配套 `tools/hookdrive.py` 逐条读场景文件驱动，场景 DSL 另有驱动侧 `close`（发 WM_CLOSE 走真实关窗路径）、`kill`、`minimize`、`expect-exit`。

代价与边界：窗口被最小化 / 隐藏时 eframe 不跑 egui pass（`wgpu_integration.rs` 的 `!show_ui` 分支），截图没有新帧 —— 只保证「被别的窗口遮挡（后台）」；不覆盖真实 DPI 切换 / IME / 物理设备特性；`tools/uicheck.ps1` 的 Win32 路径与截图回退补丁保留，作为真实 OS 输入的抽检。本能力是方便开发的脚本功能，**不迭代版本号**（`Cargo.toml` 仍为 0.1.3，只在 `CHANGELOG.md` 的 Unreleased 下记账）。备选：`egui_kittest` 需要联网新增依赖、`EFRAME_SCREENSHOT_TO` 只对 glow 后端生效（wgpu 下 panic）、`PrintWindow` 的其它 flag 已实证失败、`PostMessage` 直投鼠标消息对 egui 无效。
