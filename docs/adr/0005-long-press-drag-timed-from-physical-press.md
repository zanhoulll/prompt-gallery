# 长按拖动排序从「物理按下」计时，达标前位移即取消

侧边栏重排原以 egui 的 `response.drag_started()` 作为 280ms 计时的起点；但该事件对点击+拖动控件必须等指针位移超过 `max_click_dist`（6pt）或按住超过 `max_click_duration`（0.8s）才成立，于是计时锚点变成「开始移动」而非「按下」，出现「先长按再快速拖并快速松手不重排」「要移动后重新累计 280ms」等不可预期的现象。改为**从指针物理按下时刻计时**（`i.pointer.press_start_time()`），并在达标前累计位移超过 6pt 时**取消本次长按**：这样长按判定在「按住不动」阶段完成，与用户直觉一致，也不会让快速划过多行误触发重排。代价是「按下即立刻拖动」（未经停留）本次手势不再重排——这是有意接受的严格语义；实现上必须自建手势状态机，不能再依赖 `response.drag_started()` / `dragged()` / `drag_delta()`。曾考虑引入 `egui_dnd` 0.17（兼容 egui 0.36），但其拖拽门控不等于长按、定制长按需绕过它，且会新增 `egui_animation`、`simple-easing` 等依赖，与 ADR-0001「低占用 + 完全渲染控制」相悖。
