# 提示词扁平化为正向 + 负向两段文本（取代 ADR-0002）

> 2026-10-20 注记：实机发现「装过 0.1.x 但一条示例都没存」的空库也会启动即报错，空库没有数据可丢，报错只会被当成故障。现 `migrate()` 在 v1/v2 且 `examples` 与 `sections` 都为空时直接按 v3 形状重建；**有内容的旧库仍按下文拒绝**，迁移路径依旧不存在。

需求要求正向提示词「只留 1 个空白文本框」，并新增一段独立的负向提示词；而导入的图片提示词天然没有「质量与基础 / 人物特征 / 服装与道具 / 姿势与动作 / 环境与光影」这种分区结构。ADR-0002 用 5 个无缝 TextEdit 拼成一个框，前提正是分区标题必须不可编辑、不可选中——前提消失后，这套结构只剩维护成本，且会给「导入的提示词写进哪个分区」留下无解的歧义。

决定：数据模型从 `sections: [String; 5]` 改为 `positive: String` + `negative: String`；`SECTION_TITLES`、`join_for_clipboard` 的分区拼接、`sections` 表一并删除；数据库 `SCHEMA_VERSION` 2→3，归档 `archive_version` 1→2，`data.json` 直接写 `positive` / `negative`，不再写 5 元素数组与分区标题。

**Consequences**：分区边界不可逆地消失，旧库与旧导出包不再能读入。这是刻意放弃迁移而非疏漏：本项目是单用户私密仓库、没有存量数据，保留 v1/v2 迁移分支只为兼容一个不存在的用户，代价是每个分支都要有测试与文档。若将来真出现存量数据，另开 ADR 恢复迁移路径。负向提示词与正向提示词同权：都参与空白判定、脏标记、500ms 自动保存、复制与归档，锁定时一起只读。
